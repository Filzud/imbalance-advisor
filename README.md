# Интерпретируемый инструмент автоматического выбора метода борьбы с дисбалансом классов

Магистерская ВКР, РУДН, ФИИ, кафедра прикладного ИИ.

По новому датасету система считает **мета-признаки** → прогоняет их через обученную
**мета-модель** → рекомендует **метод борьбы с дисбалансом классов** → объясняет выбор
через **SHAP**.

Ядро — гибрид: мета-классификатор (Random Forest / Gradient Boosting на корпусе датасетов
OpenML) + интерпретирующий слой SHAP.

---

## Структура репозитория

```
.
├── config.py              # random_seed, пути, методы балансировки, реестр классификаторов
├── run_pipeline.py        # единый воспроизводимый запуск всего пайплайна (этапы 1–6)
├── app.py                 # Streamlit-демо инструмента (для защиты)
├── requirements.txt       # runtime-зависимости (точные версии = pip freeze)
├── requirements-dev.txt   # dev: optuna, streamlit, pytest, ruff
├── docs/figures/          # ВСЕ графики (PNG, dpi=200) — идут в текст ВКР
├── data/                  # raw/ processed/ + manifest.csv, meta_features.csv, labels.csv …
├── models/                # обученная мета-модель meta_model.joblib
├── logs/                  # логи прогонов (pipeline.log)
├── src/                   # модули 1–7 (+ utils)
└── tests/                 # юнит- и интеграционные тесты (покрытие ≥80%)
```

## Модули `src/`

| Модуль                | Назначение                                                        |
|-----------------------|-------------------------------------------------------------------|
| `data_collection.py`  | Сбор корпуса бинарных несбалансированных датасетов из OpenML       |
| `meta_features.py`    | Извлечение вектора мета-признаков (pymfe + собственные)            |
| `labeling.py`         | Разметка корпуса: лучший метод балансировки = метка `y`           |
| `meta_model.py`       | Обучение мета-классификатора (RF / GB), leave-one-dataset-out CV  |
| `interpretation.py`   | Слой SHAP: глобальные/локальные объяснения                        |
| `recommender.py`      | Финальный инструмент `recommend(dataset)` + CLI                   |
| `experiments.py`      | Оценка для Главы 3: сравнение с базлайнами, метрики, графики       |

## Установка

```bash
python -m venv .venv
# Windows PowerShell:
.\.venv\Scripts\Activate.ps1
# Linux/Mac:
# source .venv/bin/activate

# Runtime-зависимости (необходимы для работы инструмента):
pip install -r requirements.txt

# Dev-зависимости (нужны для подбора гиперпараметров, UI и тестов):
pip install -r requirements-dev.txt
```

**`requirements.txt`** — то, что нужно для инференса рекомендатора (numpy, pandas,
scikit-learn, imbalanced-learn, pymfe, openml, shap, matplotlib, joblib).

**`requirements-dev.txt`** — инструменты разработки и экспериментов, не нужные для
прод-инференса: `optuna` (подбор гиперпараметров, модуль 4), `streamlit` (опциональный UI,
модуль 6), `pytest`/`pytest-cov` (тесты, покрытие), `ruff` (линтер PEP-8).

Требуется **Python 3.11+**. Версии в `requirements*.txt` совпадают с `pip freeze`
(`numpy<2` — для совместимости связки shap + pymfe + imbalanced-learn).

### Обход прокси для OpenML

Если в системе прописан прокси (например, SOCKS в настройках Windows/WinINET), он может
искажать/обрезать ответы OpenML API. Модуль сбора обходит его автоматически: перед
обращением к OpenML вызывается `utils.configure_network()`, которая добавляет домены
OpenML в `no_proxy` (прямое соединение мимо прокси). Управляется флагами в `config.py`:

```python
BYPASS_SYSTEM_PROXY = True
NO_PROXY_HOSTS = "openml.org,api.openml.org,www.openml.org"
```

Прокси обходится **только** для OpenML; остальной трафик не затрагивается. Для `pip` при
установке за прокси используйте `pip install --proxy "" ...` или переменную `NO_PROXY`.

## Воспроизводимость

- Единый `RANDOM_SEED` в `config.py`, функция `utils.set_global_seed()` фиксирует
  Python / NumPy / hash-seed.
- Версии всех пакетов зафиксированы в `requirements*.txt`.
- Логи прогонов пишутся в `logs/pipeline.log`.
- Дорогие этапы (сбор корпуса, разметка) кэшируются в `data/`.

## Запуск пайплайна

Одна команда прогоняет весь путь (сбор → мета-признаки → разметка → мета-модель →
SHAP → эксперименты). Каждый этап кэширует результат, повторный запуск не пересчитывает
готовое.

```bash
python run_pipeline.py                    # весь пайплайн (с учётом кэша)
python run_pipeline.py --force            # пересчитать всё заново (включая ablation)
python run_pipeline.py --stage labeling   # только один этап
```

Этапы (в порядке зависимостей): `collect → meta_features → labeling → meta_model →
interpretation → experiments`.

## Использование инструмента

После пайплайна инструмент доступен через рекомендатор (модуль 6):

```bash
# CLI: рекомендация для произвольного бинарного датасета (CSV или OpenML id)
python -m src.recommender --csv path/to/dataset.csv --target-column target
python -m src.recommender --openml-id 310

# Streamlit-демо (для защиты): загрузка датасета → рекомендация → вероятности → SHAP
streamlit run app.py
```

На выходе: рекомендованный метод, вероятности по всем 6 методам и человекочитаемое
SHAP-объяснение + waterfall-график. Краевые случаи (не бинарный таргет, мало строк,
битый источник) сопровождаются понятным сообщением, а не трассировкой стека.

## Тесты

```bash
pytest                  # запуск тестов + отчёт по покрытию (порог ≥80%)

```

## Графики и артефакты

Любой график любого модуля сохраняется отдельным PNG-файлом в `docs/figures/`
через единый хелпер `src.utils.save_figure(fig, name)` (формат PNG, `dpi=200`,
`bbox_inches="tight"`). Эти картинки используются напрямую в тексте ВКР (Главы 2–3).

**Табличные артефакты в `data/`:**

| Файл | Модуль | Содержание |
|------|--------|------------|
| `manifest.csv`               | 1 | Корпус: did, имя, размеры, IR, диапазон IR, доля пропусков |
| `processed/<did>.csv`        | 1 | 90 обработанных датасетов (числовые, без NaN, target 0/1)  |
| `meta_features.csv`          | 2 | Матрица мета-признаков 90 × 132                             |
| `labeling_scores.csv`        | 3 | Датасет × метод × метрика (PR-AUC, F1), 540 строк          |
| `labels.csv`                 | 3 | Лучший метод на каждый датасет (целевая `y` мета-модели)   |
| `meta_model_oof.csv`         | 4 | LODO out-of-fold прогнозы и вероятности мета-модели        |
| `meta_model_comparison.csv`  | 4 | Сравнение RF vs GB (top-1, top-3)                          |
| `shap_values.npz`            | 5 | Кэш SHAP-значений (датасеты × признаки × классы)           |
| `experiments_summary.csv`    | 7 | Мета-модель vs базлайны (top-1, top-3, regret)             |
| `ablation_base_classifier.csv`| 7 | Ablation: DT vs LR (согласованность выбора метода)        |
| `models/meta_model.joblib`   | 4 | Обученная мета-модель + метаданные (классы, признаки)      |

> **Табличные результаты (`data/*.csv`) включены в репозиторий** — это итоговые артефакты
> экспериментов (корпус-манифест, мета-признаки, метки, оценки методов, LODO-прогнозы, ablation).
> **Не хранятся** только тяжёлые/полностью генерируемые данные (см. `.gitignore`): каталоги
> `data/raw`, `data/processed`, обученная модель `models/meta_model.joblib` и кэш SHAP
> `data/*.npz` — они воспроизводятся одной командой `python run_pipeline.py`.

## Ключевые результаты

- Корпус: **90 датасетов** OpenML, стратифицирован по IR (30 лёгких / 30 средних / 30 тяжёлых).
- Мета-признаки: **132** (pymfe: general, statistical, info-theory, landmarking, model-based,
  complexity Ho-Basu + собственные признаки дисбаланса).
- Мета-модель: **GradientBoosting**, LODO **top-1 = 0.34**, **top-3 = 0.61** (выше случайного 0.17
  и мажоритарного 0.24).
- **Regret 0.032**: следуя рекомендации, достигаем **94.5 % от оптимального PR-AUC** — мета-модель
  лучшая и по точности, и по близости к оптимуму среди всех стратегий.
- Тесты: **93**, покрытие **≈89 %**.
